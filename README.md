<h1 align="center">raylib-starter</h1>

<p align="center">
  My personal, minimal game template for creating cross-platform
  <a href="https://github.com/raysan5/raylib">raylib</a>
  games in Python, powered by <a href="https://github.com/pocketpy/pocketpy">pocketpy</a>.
</p>

## Features
* Includes raylib ([v6.0](https://github.com/raysan5/raylib/releases/tag/6.0)) and pocketpy ([v2.1.8](https://github.com/pocketpy/pocketpy/releases/tag/v2.1.8)), built from source and version-pinned
* Write your whole game in Python, with live hot reload while developing
* Cross-platform builds (Linux-x64, Windows-x64 & Web)
* Autogenerated Python bindings and type stubs
* Includes build helper script for easy development
* Configurable automatic asset packing/loading using a zip pak + virtual filesystem
* Persistent `save/` directory on all platforms, IndexedDB backed on web

> [!NOTE]
> The previous LuaJIT (and C/C++) version lives on the [`luajit`](https://github.com/ingur/raylib-starter/tree/luajit) branch.

## Requirements
* `git`, `cmake`, `ninja`, `zip`, and a C compiler
* Linux: OpenGL, X11 and Wayland development libraries (see `devenv.nix`)
* `emscripten` for the web target, `mingw-w64` for the windows target
* `python3` with `pycparser` and `pcpp` to run `bindgen`
* Optional: [devenv](https://devenv.sh) provisions all of the above in one shell

## Getting Started

Clone the repository:
```bash
git clone --depth 1 https://github.com/ingur/raylib-starter.git
```

Use the helper script to build and run the game:
```bash
./build.sh run
```

You can use the following commands:
```bash
# usage: ./build.sh <command> [options]
./build.sh run        # build and run the game (debug)
./build.sh linux      # build the linux target [debug|release]
./build.sh windows    # build the windows target [debug|release]
./build.sh web        # build the web target [debug|release]
./build.sh dist       # package release zips for all platforms into dist/
./build.sh bindgen    # regenerate the python bindings and type stubs
./build.sh clean      # clean build environment
./build.sh help       # show the help message
```
> [!NOTE]
> The first build compiles raylib and pocketpy from source and takes a few minutes, once. Later builds are incremental, binaries land in `build/<target>/<config>/`.

Using [devenv](https://devenv.sh)? `devenv shell` (or `direnv allow` once) provides the whole toolchain, then the same script just works.

## Example Code
```python
import raylib as rl

# top level runs once at boot, the window is already open.
# define update(), it runs every frame (return True to quit)
def update():
	rl.BeginDrawing()

	rl.ClearBackground(rl.RAYWHITE)
	rl.DrawText("Congrats! You created your first window!", 190, 200, 20, rl.LIGHTGRAY)

	rl.EndDrawing()
```

## Configuration/Tips

* Default Python entrypoint is `game/main.py`, define `update()` for the frame loop and return `True` to quit
* Window startup settings live in `game/window.py`
* Debug builds (`run` uses one) enable hot reload and the `DEV` builtin for gating debug tools, release builds never do
* Define `before_reload()` and `after_reload(state)` to free resources and carry a state string across hot reloads
* Project name and raylib/pocketpy versions can be configured in `CMakeLists.txt`, rerun `bindgen` after a bump
* Vectors and colors come from the built-in `vmath` module (`vec2`, `vec3`, `color32`)
* Assets in `assets/` and `game/` are packed into `assets.pak` (a plain zip) and loaded through a virtual filesystem, loose files win over the pak:
  ```python
  sprite = rl.LoadTexture("assets/sprite.png")
  ```
* Write save files to `save/`, it exists on every platform and persists on web, anything written elsewhere on web is in-memory only:
  ```python
  rl.SaveFileText("save/highscore.txt", str(score))
  ```
* Some raylib functions take C pointers (`intptr` in the stubs), the built-in `stdc` module bridges them with `addressof`, typed boxes like `Float`, and `malloc`/`write_bytes`
* Test web builds locally with `emrun build/web/Release/game.html`
